# web_icons — Tooling

This directory holds documentation for the `web_icons` module build pipeline.

---

## Architecture overview

`web_icons` centralises all icon fonts used by Odoo and replaces the legacy
FontAwesome 4 font with a combination of:

| Font | Family name | Purpose |
|---|---|---|
| Material Symbols (PUA subset) | `material_symbols_outlined` / `material_symbols_sharp` | Principal icon set — all `data-icon="…"` and `.fa-*` rules |
| Odoo UI Icons | `odoo_ui_icons` | Brand logos and custom pictograms (`.oi-*`, `.fa-twitter`, …) |

### Why PUA, not ligatures?

Google's variable ligature font subsets size non-linearly: adding ~130 legacy
icons (currency symbols, medical, transport…) to the 300-icon base set jumped
from 39 KB to 416 KB because those icons span different internal delta segments
in `gvar`.

The PUA approach bakes the FILL axis into two static glyph ranges and maps
them to Unicode Private Use Area codepoints:

```
U+E000 … U+E000+N-1   → outlined glyphs   (FILL = 0)
U+E000+N … U+E000+2N-1 → filled glyphs     (FILL = 1, only where fill differs)
```

Size is strictly linear (~48 bytes / glyph) regardless of which icons are in
the set.  430 icons × ~2 glyphs each → **29 KB** outlined, **27 KB** sharp.

## Generated files (do not edit manually)

| Path | Generated by | Purpose |
|---|---|---|
| `static/src/fonts/ms_pua_outlined.woff2` | `generate_icons` | Outlined PUA font |
| `static/src/fonts/ms_pua_sharp.woff2` | `generate_icons` | Sharp PUA font |
| `static/src/materialsymbols/material_symbols_outlined.css` | `generate_icons` | `@font-face` for outlined |
| `static/src/materialsymbols/material_symbols_sharp.css` | `generate_icons` | `@font-face` for sharp |
| `static/src/_icons_variables.scss` | `generate_icons` | `$icon-pua-map`, `$icon-*` SCSS vars |
| `static/src/icons_pua.scss` | `generate_icons` | Per-icon `[data-icon="…"]::before` rules |
| `static/src/data/icons_pua_map.json` | `generate_icons` | JS consumer map |

The intermediate variable WOFF2 files (`ms_outlined.woff2`, `ms_sharp.woff2`)
are downloaded from Google Fonts during the build step and can be deleted
afterwards — they are not served to browsers.

## Regenerating the fonts

Run whenever `icons_wishlist.json` changes:

```bash
python odoo-bin --addons-path=addons,../enterprise generate_icons
```

The command:

1. **Downloads** a variable WOFF2 subset from Google Fonts API (internet
   required, ~39 KB per variant).
2. **Resolves** each icon name to its glyph via the GSUB ligature table.
3. **Detects** which icons actually have a distinct filled variant by comparing
   glyph outlines at FILL=0 vs FILL=1.
4. **Bakes** the FILL axis: copies the FILL=1 glyph into the FILL=0 font under
   a `_f` name, assigns PUA codepoints to both ranges.
5. **Subsets** to PUA codepoints only, drops GSUB/GPOS/hinting → `woff2`.
6. Writes the SCSS variables, per-icon CSS and JSON map.

### Options

```bash
# Preview the wishlist without downloading anything
python odoo-bin --addons-path=addons generate_icons --dry-run

# Use a custom wishlist
python odoo-bin --addons-path=addons generate_icons --wishlist /path/to/wishlist.json
```

### Dependencies

```bash
pip install fonttools brotli
```

## Adding icons

1. Edit `static/src/data/icons_wishlist.json` — add the
   [Material Symbols](https://fonts.google.com/icons) icon name (snake_case).
2. Re-run `generate_icons`.
3. Optionally add an FA compatibility rule in `static/src/icons.scss`:
   ```scss
   .fa-my-icon { @include icon-content("my_icon"); }
   ```

To check whether an icon name is valid before adding it, look it up at
<https://fonts.google.com/icons> — use the name shown under the icon
(spaces replaced with underscores).


## CSS usage

### HTML attribute (preferred)

```html
<!-- outlined (default) -->
<span class="oi" data-icon="favorite"></span>

<!-- filled -->
<span class="oi oi-filled" data-icon="favorite"></span>
```

Both match the base `[data-icon]` or `.oi` selector in `icons.scss`, which
applies font family and sizing. `icons_pua.scss` then provides the `content:`
codepoint.

### SCSS mixin

```scss
// In any SCSS file that has $icon-pua-map in scope:
.my-element {
    @include material-icon-base;
    @include icon-content("home");                        // outlined
    @include icon-content("favorite", $filled: true);    // filled
}
```

### SCSS variable (inline content)

```scss
// content: $icon-arrow-drop-down  →  the outlined PUA codepoint for arrow_drop_down
&::after {
    font-family: 'material_symbols_outlined';
    content: $icon-arrow-drop-down;
}
```

## Fill behaviour

238 of the 430 icons have a visually distinct filled variant.  For the
remaining 192 (pure geometric shapes like `add`, `close`, `arrow_drop_down`)
the outlined and filled codepoints map to the same glyph — applying
`.oi-filled` has no visual effect, which is the correct semantic behaviour.

The `icons_pua_map.json` file records this distinction:

```json
{
  "favorite": { "outlined": "\uE09E", "filled": "\uE24C" },
  "add":      { "outlined": "\uE006", "filled": "\uE006" }
}
```
